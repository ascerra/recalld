## Preexisting pending operations: unresolved design boundary

The fresh guard prevents new dead ends; it does **not** solve old pending
operations. The retained policy hash includes the entire NamespaceConfig, so a
certification cutover changes that hash. Offline inspection/remedy rejects
unresolved batches before provider work. There is no sanctioned generic cancel
or operator-abort seam in the inspected code. Existing BatchItemRejected is for
actual terminal validation failures, not a fabricated way to discard pending
intent. No hash rewrite, automatic draining, forced purge, fake invalid input,
old-vector blessing or rollback is proposed.
