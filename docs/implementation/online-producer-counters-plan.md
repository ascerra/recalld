## One request decision and truthful outcomes

The existing tracing target remains disabled by default. Whole-request selection uses the existing sampling decision/rate, inherited by nested adapter/engine calls and explicit blocking workers. Unsampled/disabled paths do not evaluate event arguments, sample instrumentation clocks, allocate trace state or increment new instrumentation counters. Existing normal work remains unchanged. Source-local counters are selected-request observations, not extrapolated population counts. The external benchmark must independently retain complete attempts/completions/errors/latencies; a selected-root ordinal is not a completed request denominator.

Transport context begins before request intent has been decoded. Do not pass an invented `record_access=false` as user intent. If the current boolean-only `measure` signature cannot express this, add the narrow actual transport consumer entrypoint with unknown/absent intent while preserving the existing known-boolean request API and event compatibility. The parsed operation can emit a bounded category later; no second sampling decision. No arbitrary method strings as metric labels. The same root must include response serialization and actual write/flush, not finish when the handler yields a value.

Keep request/child span identifiers and nesting so adapters/lock waits are not double-summed with parent wall time. Non-overlapping top-level intervals plus residual account for the request; concurrent worker durations remain nested. Existing synchronous sink emission cost stays in caller latency (later intervals/residual as applicable). An I/O-failing trace writer must not replace domain results. Arbitrary subscriber panic is not covered by that guarantee, particularly during Drop/unwind.

Known success/error counts come from actual returned results. Dropped futures and worker join uncertainty retain ambiguous cancellation/error/unwind classification unless the boundary proves more. Canonical committed-but-publication-failed stays committed with its original receipt; serialization/socket failure after commit must not become a rolled-back write or duplicate-safe retry. Do not inspect error strings to recover commit state when typed results exist.
