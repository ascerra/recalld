## Actual defect and narrow correction

PR146's parent ran RIF Off, so its multiplier 1 and score details were truthful there. PR102 separately recomputed original contributions after suppression. A mechanical composition left returned explanations describing Off inputs even though experimental scores/effective R had changed. The actual QueryEngine regression failed with reported multiplier **1.0** versus applied **0.85012245**. This is a composition defect, not a regression claim against either independently scoped parent.

The correction refreshes explanation bookkeeping at PR102's existing recomputation loop. Each original contribution is still recomputed exactly once; formulas, arithmetic, temporal application, frozen anchors, eligibility and work/pair/target/cumulative caps are unchanged. The chosen own explanation follows the maximum own score. Eligible inherited origins retain their maximum recomputed contribution by UUID, preserving distinct metadata/graph rediscovery inputs until that maximum is selected. Equal contributions retain the existing deterministic first contribution; final ranking remains score/UUID ordered.

`OwnScoreExplanation.rif_multiplier` reports the actual multiplier applied to that origin's effective retrievability. The returned `ScoreExplanation.rif_multiplier` reports the returned record's multiplier, which can remain 1 while a predecessor's contribution is suppressed. Neither is a multiplier to apply again to the final score. Suppressed effective R is already present in the inputs used to reconstruct each base score. Raw R remains canonical/projected; no stability or lifecycle record is written.

Off stays default. Shadow keeps the identical Off explanation and applied multipliers of 1; its hypothetical multipliers remain in existing RIF diagnostics. Experimental mode refreshes both own and inherited details and preserves `max(own, inherited)`, without a second temporal boost. The original explicit-false requirement remains: selecting operator RIF never rewrites true intent into a read-only request.

The parent integration carries `self.rif_mode` through the existing `pin_read_engine` constructor and retains the synchronous pinned `ReadHandle` graph adapter. It does not reintroduce the older inline constructor, acquire the live graph lock again, or sample another clock/policy.
