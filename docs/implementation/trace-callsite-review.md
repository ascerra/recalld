## Pinned dependency contract and source

Cargo.lock pins `tracing`0.1.44, `tracing-core`0.1.36 and `tracing-subscriber`0.3.23. Exact source hashes and rlib hashes are in [VALIDATION.json](evidence/trace-callsite/VALIDATION.json), with [captured outcomes](evidence/trace-callsite/RESULTS.txt) and committed drivers/probe. Primary source paths below are relative to their pinned crate roots in the retained Cargo source cache; no claim about an uninspected newer release.

- `tracing-core/src/subscriber.rs:105–181`: `register_callsite` promises registration at least once for every active subscriber. `Always`/`Never` describe fixed interest; filters dependent on runtime context or sampling must return `Sometimes`. A subscriber that actually changes its filter must rebuild its own cached interest.
- `tracing-core/src/callsite.rs:13–52`: registering a callsite combines the interests of active subscribers; creating a new Dispatch rebuilds the cache.
- The test capture is only a writer plus the stock static target filter in `src/performance_tests.rs`. It declares no custom interest and changes no filter. `tracing-subscriber/src/filter/env/directive.rs:66–68` marks span-name/field directives dynamic; our target/level directives have neither. `filter/env/mod.rs:641–662` returns `Always` for statically enabled metadata, otherwise its base interest. This declaration is consistent with the documented contract. Application request sampling occurs outside the subscriber and does not turn this static target filter into a subscriber-owned changing filter.
- `tracing-core/src/callsite.rs:310–340`: first registration caches rebuilt interest; concurrent registration falls back to `Sometimes`, not an unconditional drop. `subscriber.rs:674–692`: `NoSubscriber` returns `Never` and disables metadata.
- `callsite.rs:545–570`: when the registry has one live Dispatch, `Rebuilder::JustOne` consults the registering thread's current default. The untraced thread sees `NoSubscriber`; its `Never` is cached even though the live scoped fmt Dispatch would enable the callsite. Multi-dispatch registration iterates the stored registry instead. The second-Dispatch diagnostic exercises that distinction.
- `dispatcher.rs:841–852` installs a scoped default but does not rebuild callsite interest. `tracing/src/macros.rs:1214–1241` consults cached interest before the active dispatcher for `enabled!`. A cached `Never` can therefore prevent the later active filter from being consulted.
- `tracing/src/instrument.rs:380–389` installs the captured dispatcher for each future poll. The actual MCP test uses this ordinary context propagation unchanged; it is not omission of `with_subscriber` around the request.

The observed mechanism is in the pinned single-dispatch registration/cache path, not an invalid dynamic-interest declaration by this test capture. A scoped subscriber's lifetime and another thread's default identity are distinct from changes to that subscriber's static filter. No assertion is made that every tracing context or global-dispatch deployment loses events.
