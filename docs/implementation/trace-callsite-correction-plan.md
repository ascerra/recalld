## Concrete choices

| Choice | Actual production change | Limit/cost |
| --- | --- | --- |
| Released update | None currently available in inspected sources | Cannot claim fixed by updating Cargo.lock today. |
| Exact Git pin to3614 | Cargo patch/lock pins the above revision | Broader dependency changes and unmerged concurrency code; needs upstream regression and application validation. |
| Release-only backport of3614 | Retain released core manifests/features; vendor exact core with attributed callsite patch via Cargo patch | Fixes dependency mechanism, but adds maintained dependency source and requires reentrancy/contention/no-std tests. Mechanical patch check only so far. |
| Application entry guard | One shared `performance::target_enabled` change; dependencies unchanged | Contains this application's cold untraced registration; does not repair other tracing callsites or recover already-poisoned caches. |

**Recommend validating the application entry guard first**, because every performance event is behind the existing shared gate and request spans are behind its selected decision. The implementation would short-circuit TRACE's public `STATIC_MAX_LEVEL`/`LevelFilter::current()` checks, then inspect whether the current dispatcher is `tracing::subscriber::NoSubscriber`. Only an actual subscriber reaches the existing target-specific `tracing::enabled!`. End the `get_default` callback before evaluating that macro: nesting it inside the callback would hit tracing's documented reentrancy suppression. Do not replace target filtering with a broad level-only test.

This avoids the invalid first registration at its common application entry point without a second subscriber, cache reset, serialization or changed interest declaration. The existing `REQUEST` decision still takes precedence; no new sampling, clock, allocation, dispatcher clone, context wrapper or worker ownership is intended. The globally disabled fast path must return before the dispatcher inspection. When tracing is globally enabled but this thread is untraced, the new dispatcher inspection is additional work; no overhead claim is made without measurement. Active target-filtered and unsampled paths must retain zero application allocations/clock reads under their existing test definitions.

The guard cannot fix arbitrary tracing users, pre-poisoned performance callsites reached outside the shared gate, or other upstream registry races. The standalone raw-tracing probe would intentionally remain RED for the underlying dependency. If actual MCP/daemon controls reveal an uncovered application callsite, do not add scattered guards: reassess the release-only backport as the next concrete option. Do not weaken capture interest or introduce a fake subscriber to obtain green.
