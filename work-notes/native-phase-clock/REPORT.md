## Defect and agreed rule

The test uses actual legacy insertion, schema migration and explicit lifecycle
migration. Creation/access time 1000 and migration time 2000 legitimately produce
`lifecycle_updated_at=1000`, `phase_changed_at=2000` and `legacy_inferred` origin.
Native forget with clock 500 previously changed the phase marker to 1000. The
operation, keyed replay and strict reopen succeeded before the final assertion
reported the regression. No canonical row was authored to construct the fixture.

A3 section 8's unknown-history migration marker remains immutable. Section 3's
effective time remains `max(sample,lifecycle_updated_at)`. The correction applies
section 10's monotonic requirement to an actual new phase change by setting its
marker to `max(effective_now,old_phase_changed_at)`. Thus the reproduced case now
retains marker 2000 while updated time remains 1000. This is a clamped logical
marker, not invented historical attribution. Anchor, provenance, observation,
retrieval, reinforcement, compatibility access time and history remain unchanged.
One new mutation samples the clock once; matching replay samples it zero times.
An already-terminal record remains unchanged.

## Explicit historical compatibility

New forget receipts contain `phaseTimeRule: "monotonic_marker_v1"`. An absent
field retains the exact original PR79 computation and serialization. Insertion
neither emits nor accepts the rule. Unknown, null and numeric values fail closed;
a marked proof cannot fall back to the old computation after validation fails.
The same conditional helper produces new state and validates recorded outcomes.
Request identity, operation identity and receipt generation semantics do not change.

The old logical fixture was generated by the failing BEFORE runtime using the
production exporter. Its SHA-256 is
`c411d6abec5814d7467865f33b815a35aef8ba7c35a12f41edeb3f3c54738aaa`.
Under corrected code it passes actual import, strict native reopen, keyed replay,
re-export/import and retained-state backup/fork restore. Old receipt bytes and
original schema publication remain unchanged; old marker 1000 is not repaired
retroactively. After fork, historical receipts remain present but old-lineage
requests are rejected. No foreign generation comparison or provenance rewrite.

Older readers reject the new proof field through `deny_unknown_fields`. This is
intentional fail-closed behavior, not full backward format compatibility or
permission to use an older writer after a new tagged receipt exists. That older
decoder behavior follows its code; no separate old-binary/new-store execution
is claimed. Ordinary schema-2/public contract-v2 serving remains gated.
