## Metric contract, grounded in the pinned source

Official sources: [BEIR evaluation](https://github.com/beir-cellar/beir/blob/1ea9387afb52cb32f89d6343774c34d853eed2cd/beir/retrieval/evaluation.py), [BEIR custom metrics](https://github.com/beir-cellar/beir/blob/1ea9387afb52cb32f89d6343774c34d853eed2cd/beir/retrieval/custom_metrics.py), [pytrec_eval wrapper](https://github.com/cvangysel/pytrec_eval/blob/0d8571efc2dea5a792358410d5affbe0ad383602/py/__init__.py), [trec_eval](https://github.com/usnistgov/trec_eval/tree/d95ca64e14a47d763ae349fb65e6d8cde4141dbd).

- Call official `EvaluateRetrieval.evaluate(qrels, run, [5,10,20,100], ignore_identical_ids=False)` and `evaluate_custom(...,[10],metric="mrr")`. Reject query/document ID collisions in preflight; do not let BEIR's default remove an actual result. Publish primary nDCG@10, Recall@5/10/20, MAP@100 and MRR@10, preserving complete reference outputs/per-query diagnostics and five-decimal official aggregates.
- Qrel grades are exact integers0–3 for this synthetic track (no bool, float or negative). nDCG uses **linear grade/log2(rank+1)**, not `2^grade-1` (`m_ndcg_cut.c:24–31,68–71`). MAP/Recall use grade≥1 (`m_map_cut.c:54–74`, `m_recall.c:53–71`); custom MRR uses grade>0 (`custom_metrics.py:18–28`). MAP@100 divides by all relevant judged documents, including those outside returned100, not min(relevant,100).
- Rank-to-score policy `public-order-descending-integers-v1`: for one-based public rank r≤100, reference score is `float(101-r)`. Record original rank/UUID/document ID and any exposed score separately; adapter scores **are not engine scores**. Compact public payload need not contain a score. No reorder by stable source ID, gold relevance or UUID; no recovery of hidden ties. Reject duplicate identities before mapping. This strict unique sequence preserves public order through both official helpers.
- Native reference ties differ: trec_eval `form_res_rels.c:275–284` sorts equal scores by descending document ID; BEIR custom MRR uses Python stable insertion order (`custom_metrics.py:15–18`). Characterize both with explicit tied fixture permutations; do not call them one universal tie contract. Actual adapter inputs have no ties; engine ties remain in its observed public order and independent-run differences are retained.
- Unjudged returned documents remain at their actual rank, give zero gain/no binary credit and are counted explicitly. `pytrec_eval.cpp:364` leaves judged-only off; `form_res_rels.c:177–188,226–247` retains nonpool/negative-unjudged positions. Do not remove them or infer unknown grades. This track represents unjudged by absence from qrels, rather than feeding unsupported negative grades.
- Manifest query roster distinguishes `known` qrels, `unknown_annotations`, successful empty retrieval, and failed/missing outcome. Known qrels must contain at least one explicit judgment; a zero-positive query uses real grade0 judgments, not a dummy document. Empty qrel dictionaries are rejected as ambiguous/unsupported here. Unknown annotations remain in episode counts and binary diagnostics but outside official scored population, with explicit IDs/reason. A successful empty ranking is `{qid:{}}`, contributes zero for a known query, and must survive installed-reference verification. Never turn a failed/missing response into an empty result.
- Before reference dispatch, every scheduled query must have exactly one acknowledged terminal outcome; any failed/missing/duplicate query invalidates aggregate output. For the known population, require identical qrel/run/reference-output key sets. This defeats `pytrec_eval.cpp:601–609` skipping unknown IDs and BEIR evaluation.py:73–84 averaging only returned metric keys; custom MRR separately divides by len(qrels). No failed-arm/query intersection. Zero known queries: explicit unscored/null aggregate, no reference division by zero. Known zero-positive queries contribute official zeros but remain **unscored** in the existing A6 binary-source diagnostic. Publish both denominators; do not relabel graded nDCG or MAP as binary all-required.
